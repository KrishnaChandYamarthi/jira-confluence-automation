# How to Fill Out the Status Report Template

Use `template.md` as your starting point for each report. Copy it, rename
it (e.g., `2026-01-10-status-report.md`), and fill in each section as
described below.

## Header
- **Date:** The date you are submitting the report (not the period start).
- **Reporting Period:** The date range this report covers.
- **Prepared by:** Your name (or your team's name, if submitted on behalf
  of a team).

## Accomplishments
- List only things that were **completed** during the period — not
  in-progress work.
- Keep each bullet to one line; be specific (e.g., "Deployed v2.3 to
  production" rather than "Worked on deployment").
- If nothing was completed, write "No completed items this period" rather
  than leaving it blank.

## Blockers
- List anything currently preventing progress, with a short note on
  impact (e.g., who/what is affected, and since when).
- If there are no blockers, write "None" — don't delete the section.
- Escalation-worthy blockers should be flagged clearly (e.g., prefix with
  "URGENT:").

## Next Week's Plan
- List the top priorities for the upcoming period, in order of
  importance.
- Keep it to 3–5 items; this is a plan, not an exhaustive task list.

## Notes / Risks
- Optional section for anything that doesn't fit elsewhere: upcoming
  risks, dependencies on other teams, or context stakeholders should be
  aware of.
- Remove this section only if truly not needed for that report.

## General Tips
- Keep the whole report scannable — use bullet points, not paragraphs.
- Avoid jargon or ticket IDs if the audience is non-technical
  (stakeholders); include them if the audience is your engineering team.
- Aim to keep the report under 20 lines total.
